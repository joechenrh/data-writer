Column Comment Options

Use SQL COMMENT clauses on column definitions to control data generation behavior.

Mutually exclusive: set cannot be combined with mean/stddev/order/compress/max_length/min_length (only null_percent is allowed alongside it). mean/stddev cannot be combined with order.

Option Description Example
null_percent Percentage of NULL values (0-100) COMMENT 'null_percent=20'
max_length Max length for string types (CHAR, VARCHAR, TEXT) COMMENT 'max_length=120'
min_length Min length for string types, defaults to 75% of max_length COMMENT 'min_length=60'
mean Mean for numeric distributions (INT, BIGINT, FLOAT, etc.) COMMENT 'mean=100'
stddev Standard deviation for numeric distributions COMMENT 'stddev=15'
compress Compression ratio hint (1-100), lower = more repeated values COMMENT 'compress=40'
set Allowed values as JSON array, supports strings and integers COMMENT 'set=["ok","warn"]' or 'set=[1,2,3]'
order Integer ordering: total_order (strictly increasing), partial_order (mostly increasing), random_order (default) COMMENT 'order=partial_order'
Combined examples
`c` char(120) COMMENT 'max_length=120, min_length=120'
`score` int COMMENT 'mean=100, stddev=15'
`rank` int COMMENT 'order=partial_order'
`text_col` text COMMENT 'max_length=20000, compress=40'
`status` varchar(10) COMMENT 'set=["active","inactive","pending"]'
`nullable_col` int COMMENT 'null_percent=30'
`id_set` int COMMENT 'set=[1,2,3,4,5]'
Custom Generators (Go)

Override a column's default data generator with a Go function. At EC2 build time, data-writer compiles your code into the worker binary — generator calls are nanosecond-cost.

How it works: Click Scaffold from SQL to produce a package user file with one commented-out function per column. Uncomment the columns you want to customize; leave the rest as-is and they'll use the builtin generator.

Function shape
// gen:column device_finger
func DeviceFinger(ctx *gen.Ctx) any {
    return fmt.Sprintf("%x", sha256.Sum256([]byte(ctx.String("user_id"))))[:12]
}

The // gen:column <name> directive above each function is required and must exactly match the SQL column name. The function name itself (PascalCase) is only a valid Go identifier — the directive is authoritative.

Return type must match the column's SQL type:

SQL TypeReturn Go Type
TINYINT/SMALLINT/MEDIUMINT/INT/YEARint32
BIGINTint64
FLOAT/DOUBLEfloat64
CHAR/VARCHAR/TEXT/BLOB/VARBINARY/TINYBLOBstring
TIMESTAMP/DATETIME/TIME/DATEtime.Time
Anynil → produces SQL NULL

The *gen.Ctx API gives you:

MemberDescription
ctx.RowIDint64 absolute row number across the whole task
ctx.Rng*math/rand.Rand — worker-local, already seeded. Use ctx.Rng.Int63n(n), ctx.Rng.Int31n(n), ctx.Rng.Float64(), etc.
ctx.Int32(col) / Int64 / Float64 / String / TimeRead a sibling column's value in the current row
ctx.IsNull(col)Check if a sibling column is SQL NULL

Sibling-read rules:

  • You may only read columns that appear earlier in CREATE TABLE than the current column. Reading a later column panics at runtime.
  • Using the wrong accessor type (e.g. ctx.Int64 on a VARCHAR column) panics.
  • Reading a non-existent column name panics.
More examples
// gen:column user_id
func UserId(ctx *gen.Ctx) any {
    return ctx.Rng.Int63n(5_000_000) + 1
}

// gen:column login_name
func LoginName(ctx *gen.Ctx) any {
    return fmt.Sprintf("user_%d", ctx.Int64("user_id"))
}

// gen:column created_at
func CreatedAt(ctx *gen.Ctx) any {
    return time.Now().Add(-time.Duration(ctx.Rng.Int63n(86400*30)) * time.Second)
}

Imports: "dataWriter/src/gen" is always needed. Add "time", "fmt", "crypto/sha256", etc. as your code requires. Stdlib only — no third-party packages.

Only EC2 execution is supported for tasks with custom generators. The UI will force target=ec2 when the editor has content.
